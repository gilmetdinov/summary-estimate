## 18. F1/H1 — потеря ведущего нуля в project_code

**Файл:** `smeta_render.py`, `render_smeta()` / `render_svodnaya()` / `render_izyskaniya_placeholder()`

**Проблема:** `proj_num = int(project_code) if project_code.isdigit() else ...` — для `"04"` даёт `4`,
CONCATENATE в E1 теряет ноль (`Приложение №3.4.1` вместо `3.04.1`). При этом A6 сохраняет `"04"`
(там F6 = project_code без int). Несоответствие.

**Суть:** Убрать `int()` во всех трёх местах, писать `project_code` как строку напрямую
в F1/H1. CONCATENATE работает со строкой корректно.

**Проверка:** `project_code = "04"` → F1 = `"04"`, E1 = `Приложение №3.04.1`, A6 = `СМЕТА № 04.01.01`.

## 19. O/P колонки для госэкспертизы

**Файл:** `smeta_render.py`, `render_svodnaya()`

**Проблема:** В цикле entries условие только на `_placeholder == "izysk"`. Госэкспертиза
проваливается без O/P, хотя `cfg.unit_cost_gosexp` в конфиге есть.

**Суть:** Добавить `elif en.get("_placeholder") == "gosexp"`:
- `O = cfg.unit_cost_gosexp`
- `P = =F{R}/O{R}*1000` (стоимость госэкспертизы в колонке F, как у проектных)

**Проверка:** При включённой госэкспертизе строка получает O/P (значение + формула).

## 20. first_proj — только для проектной сметы (не для изысканий)

**Файл:** `smeta_render.py`, `render_svodnaya()`

**Проблема:** `first_proj` срабатывает на первом entry независимо от типа. Если первой
в entries идёт смета изысканий (suffix="03"), флаг тратится впустую — единичная стоимость
попадает в O изысканий (и с формулой от F вместо E), а проектные остаются без O/P.

**Суть:** Усилить условие: `if first_proj and en.get("_placeholder") is None and en["column"] == "proj"`.

**Проверка:** При raw с изысканиями первой строкой — проектные всё равно получают O/P;
изыскания обрабатываются отдельной веткой.

## 21. Границы колонки D в итоговых строках листов смет

**Файл:** `smeta_render.py`, `render_smeta()` / `render_izyskaniya_placeholder()`

**Проблема:** Во всех итоговых строках (`Итого по разделу`, `Итоги по смете`, `Итого Поз.`)
пишутся колонки A/B/C/E через `_put`, а колонка D (4) — пропускается. В шаблоне D49–D51
имеют thin-границы со всех 4 сторон, в выводе ячейка без оформления → «дыра» в рамке
таблицы на месте колонки D.

**Суть:** Добавить `_put(ws, R, 4, None, S["D49"])` / `S["D50"]` / `S["D51"]` во все
три итоговые строки `render_smeta` и оба итога `render_izyskaniya_placeholder`.
Доноры — соответствующие ячейки строк 49/50/51 шаблона (все с полными thin-границами).

**Проверка:** D-ячейки во всех итоговых строках всех листов смет имеют
`left=thin right=thin top=thin bottom=thin`.

## 22. SUM в листе-заготовке изысканий пропускает раздел 3

**Файл:** `smeta_render.py`, `render_izyskaniya_placeholder()`

**Проблема:** `last_data = R - 3` даёт сдвиг на 1: для 3 разделов data-строки 23, 26, 29,
R после цикла = 31, `last_data = 28`, `range(23, 29, 3)` = [23, 26] — нет 29.
SUM `=SUM(E23,E26)` всегда пропускает Раздел 3 (Составление отчета).

**Суть:** `last_data = R - 2`. Для N разделов сдвиг от R до последней data-строки всегда 2
(структура: секция → data → пропуск, R всегда на 2 строки вперёд от последней data).

**Проверка:** SUM = `=SUM(E23,E26,E29)` — все 3 раздела.

## 23. config_from_strings съедает нулевую ед. стоимость

**Файл:** `config.py`, `config_from_strings()`

**Проблема:** `_num("0") or base.value` → `0.0 or base.value = base.value` (0.0 falsy).
Пользователь не может ввести ед. стоимость = 0 через форму.

**Суть:** Заменить `or` на хелпер `_none_or(v, default)` — `v if v is not None else default`.
Затрагивает все три `unit_cost_*`.

**Проверка:** `config_from_strings({'unit_cost_proj': '0'}, base)` → `0.0`, пустая строка → `base`.
