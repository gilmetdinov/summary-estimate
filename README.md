# Автоматизация сметных форм (ПИР) — PoC

RND по автоматизации подготовки печатных сметных форм и сводных смет
на проектно-изыскательские работы (ПИР). См. полный разбор 4 направлений в конце.

## Что уже работает (PoC #1: выгрузка → печатный комплект)

Конвертер превращает «сырую» выгрузку отдельных смет в готовый фирменный печатный
комплект (формат эталона `sources/example.xlsx`):

* парсит каждый лист сметы в структурную модель (позиции, обоснования МНЗ,
  расчёты, разбивка ПЗ/ППО/ТКР/ПОС/ООС/ПБ/СМ/Котн, итоги, НДС);
* рендерит листы смет в фирменный бланк с **полным сохранением оформления**
  (Times New Roman, рамки, объединения, форматы чисел, курсив подстрок,
  высоты строк, область печати) — стили копируются вживую из эталона-донора;
* собирает **сводную смету** со ссылками на листы отдельных смет, НДС и
  **суммой прописью** (формула считается в Excel/LibreOffice);
* печатная сводная помещается на одну портретную страницу.

### Запуск

**Десктопное окно (для сметчицы, рекомендуется):**

```bash
python3 app.py            # откроется окно программы (tkinter)
```

Выбрать выгрузку(и) ГС → поправить реквизиты/ФИО → при необходимости включить строки
изысканий/госэкспертизы → «Конвертировать» → указать, куда сохранить (файл для одной
выгрузки, папка для нескольких). Реквизиты предзаполняются из `config.json`.

**CLI:**

```bash
python3 smeta_render.py вход.xlsx                       # один файл; имя результата
                                                       #   подберётся из содержимого:
                                                       #   Сводник_<проект>_<объект>.xlsx
python3 smeta_render.py вход.xlsx -o отчёт.xlsx         # явное имя результата
python3 smeta_render.py a.xlsx b.xlsx c.xlsx -o out/    # батч → папка (имена по содержимому)
python3 smeta_render.py вход.xlsx отчёт.xlsx            # legacy-форма (in out)
# --config config.json (реквизиты), --donor template.xlsx (оформление, по умолчанию)
```

**Проверка (smoke-тест через LibreOffice — пересчёт формул):**

```bash
python3 smoke_test.py                  # по умолчанию sources/raw.xlsx → PDF; печатает OK/FAIL
python3 smoke_test.py путь/выгрузка.xlsx
python3 smeta_parser.py sources/raw.xlsx   # отдельно — проверка модели парсера
```

**Сборка автономного `.exe` (для раздачи без Python):** см. `БЕТА.md`. Коротко —
`build.bat` на Windows (PyInstaller кросс-компиляцию не умеет, exe собирается только
на винде); `build.sh` на macOS/Linux для локальной проверки сборки.

### Файлы

**Функциональные (коммитятся в репозиторий):**

| Файл | Назначение |
|------|------------|
| `smeta_parser.py` | парсер выгрузки → структурная модель (`Smeta`) |
| `smeta_render.py` | единый entrypoint (CLI) + re-export публичного API для `app.py`/PyInstaller |
| `render/` | пакет рендеринга: `convert.py` (оркестрация), `sheet_smeta.py` / `sheet_svodnaya.py` / `sheet_izyskaniya.py` (листы), `donor.py` (мастер-шаблон), `style.py` (хелперы openpyxl) |
| `config.py` / `config.json` | реквизиты подписантов, ставка НДС, опц. изыскания/госэкспертиза |
| `app.py` | десктопное окно (tkinter) |
| `make_template.py` | генератор мастер-шаблона из эталона |
| `template.xlsx` | **мастер-шаблон-донор** (2 листа-донора); вкладывается в exe |
| `smoke_test.py` | прогон + рендер через LibreOffice (проверка формул) |
| `tests/` | юнит-тесты (`pytest`): парсер, хелперы рендеринга, конвертация |
| `build.spec` / `build.bat` / `build.sh` | сборка автономного бинаря (PyInstaller) |
| `app.ico` / `app_icon.png` | иконка приложения (файл exe + окно/панель задач) |
| `requirements.txt` / `requirements-build.txt` | рантайм / сборочные зависимости |
| `README.md` / `ROADMAP.md` / `CLAUDE.md` / `БЕТА.md` | документация |

**Локальные данные `sources/` (в `.gitignore`, не коммитятся):**

| Файл | Назначение |
|------|------------|
| `sources/example.xlsx` | эталон формата; **источник** для `make_template.py` |
| `sources/raw.xlsx` | образец входа для тестов/smoke |
| `sources/*_converted.xlsx`, `*.pdf` | образцы результата/превью |

> `sources/` под `.gitignore` намеренно: там лежат реальные сметы заказчиков, которым
> не место в репозитории. Сам мастер-шаблон `template.xlsx` уже сгенерирован и закоммичен,
> поэтому без `sources/` всё работает; `example.xlsx` нужен только чтобы перегенерировать
> шаблон (`python3 make_template.py`).

## Архитектура

```
выгрузка из сметной программы (xlsx)
        │
        ▼   smeta_parser.py — классификация строк по содержимому
   структурная модель (Smeta: разделы, позиции, подстроки, итоги)
        │
        ▼   render/ — инъекция в шаблон, стили из донора
   фирменный печатный xlsx (листы смет + сводная со ссылками)
```

Принцип: оформление **не генерируется руками**, а копируется из файла-донора —
поэтому соответствие печатной форме максимальное. Донор — выделенный мастер-шаблон
`template.xlsx` (два листа-донора со стабильными именами), генерируется из эталона
`sources/example.xlsx` командой `python3 make_template.py`.

## Известные ограничения (для дальнейшего харднинга)

* **Изыскания (НЗ_ИГДИ):** парсер многосекционный и готов; в сводную строку изысканий
  можно добавить вручную (форма/конфиг), но нужен тест на реальной смете изысканий
  (разделы Полевые/Камеральные/Отчёт), которой в образце входа не было.
* **Строка госэкспертизы / изысканий** в сводной — вставляется вручную через форму или
  `config.json` (эти данные не приходят из выгрузки ГС). Автогенерации нет — так и задумано.
* **ФИО/реквизиты подписантов** — вынесены в `config.json` и редактируются в окне
  программы (хардкода в коде больше нет).
* **Номера через формулы-драйверы** (как `F6`/`H7` в эталоне) заменены на готовые
  значения — визуально идентично; при желании вернуть driver-cell подход.
* **Авто-высота строк** позиций полагается на пересчёт в Excel/LibreOffice.

## RND: 4 направления

1. **raw → печатный бланк одного проекта** — ✅ реализовано (этот PoC).
2. **Сводный отчёт по нескольким проектам** — следующий инкремент: тот же паттерн
   уровнем выше (свод сводов); агрегация = суммы, надёжнее консолидировать
   значения в один workbook, а не линковать файлы.
3. **Шаблоны/автоматизация в Гранд Смете + сводные ПИР** — ГС умеет ПИР (СБЦ и
   новые МНЗ по 707/пр; изыскания), но богатого API нет. Оптимум — гибрид:
   ГС считает сметы → внешний конвейер (п.1–2) строит сводки и печать.
4. **Конвертер Адепт → Гранд Смета** — реализуемо через АРПС 1.10 (лоссово) или
   XML Минстроя (перспективнее, но схема слабо специфицирована, нужен маппинг
   под вендора). Для ПИР возможен ПИР-aware маппер.
